# دليل تشغيل Dental Hub CRM على سيرفر

الدليل ده بيمشي معاك خطوة بخطوة، من شراء السيرفر والدومين لحد ما الفريق يسجّل دخول على
`https://crm.<الدومين بتاعك>`. بعد كده فيه الشغل اليومي: التحديث، والرجوع لنسخة قديمة،
والنسخ الاحتياطي والاسترجاع، ولو حاجة وقفت.

كل الأوامر مكتوبة زي ما هي، انسخها والصقها. أي حاجة بين `< >` غيّرها بالقيمة بتاعتك
(من غير العلامتين). في الأمثلة الدومين هو `crm.example.com`.

## 1. هتحتاج إيه

- حساب على [Hetzner Cloud](https://console.hetzner.cloud/) وكارت للدفع.
- دومين (مثلاً `example.com`) من أي شركة دومينات، والصلاحية إنك تعدّل الـ DNS بتاعه.
- حساب GitHub عنده صلاحية على الريبو `allinagencyegy-glitch/dental-hub-crm`.
- جهازك (Windows أو Mac أو Linux). أمر `ssh` موجود جاهز في الثلاثة: في Windows افتح
  **PowerShell**، وفي Mac افتح **Terminal**.

الوقت: حوالي ساعة أول مرة، أغلبها استنى الـ DNS والتثبيت.

## 2. مفتاح SSH على جهازك

المفتاح ده هو اللي بيدخّلك السيرفر بدل كلمة السر. اعمله مرة واحدة على جهازك:

```bash
ssh-keygen -t ed25519 -C "<اسمك>"
```

دوس Enter على كل سؤال (أو اكتب كلمة سر للمفتاح لو حابب، وده أحسن). بعدها اعرض المفتاح
العام وانسخه كله:

```bash
cat ~/.ssh/id_ed25519.pub
```

السطر بيبدأ بـ `ssh-ed25519`. ده اللي هتلصقه في Hetzner. الملف التاني
`~/.ssh/id_ed25519` (من غير `.pub`) سرّي، ما يتبعتش لحد ولا يتنقل من جهازك.

## 3. شراء السيرفر من Hetzner

من Hetzner Cloud Console: اعمل Project جديد (مثلاً `dental-hub`)، وبعدين **Add Server**:

| الاختيار | القيمة |
|---|---|
| Location | Nuremberg أو Falkenstein (ألمانيا، الأقرب لمصر) |
| Image | **Ubuntu 24.04** |
| Type | **CX23** (Shared vCPU، Cost-Optimized) |
| Networking | خلي **Public IPv4** متعلّم عليه. ناس كتير في مصر ما عندهاش IPv6 |
| SSH keys | **Add SSH key** والصق السطر من الخطوة 2 |
| Backups | علّم عليه. ده نسخة من السيرفر كله برّه السيرفر (شوف الخطوة 10) |
| Name | مثلاً `dental-hub-crm` |

الباقي سيبه زي ما هو، ودوس **Create & Buy now**. بعد دقيقة هيظهر السيرفر ومعاه الـ
**IPv4**، رقم زي `203.0.113.10`. انسخه، هتحتاجه في الخطوة الجاية.

مش محتاج تعمل Firewall من Hetzner: السكربت بيقفل كل حاجة على السيرفر نفسه ما عدا SSH و
HTTP و HTTPS.

## 4. الدومين وسجل الـ DNS

ادخل على لوحة الـ DNS عند شركة الدومين، وضيف سجل واحد:

| Type | Name / Host | Value | TTL |
|---|---|---|---|
| `A` | `crm` | الـ IPv4 بتاع السيرفر | أقل حاجة متاحة (مثلاً 5 دقايق) |

كده `crm.example.com` بيشاور على السيرفر. ملاحظات:

- لو فيه سجل `AAAA` لنفس الاسم `crm` (أحياناً بيكون موجود من صفحة الـ parking) امسحه.
  لو بيشاور على مكان تاني، شهادة HTTPS بتفشل.
- لو الدومين على **Cloudflare**: خلي السجل **DNS only** (السحابة رمادي مش برتقاني).
- اتأكد إنه اشتغل من جهازك. لازم يطلع الـ IP بتاع السيرفر:

  ```bash
  nslookup crm.example.com
  ```

  غالباً بياخد دقايق، وساعات لحد ساعة. تقدر تكمّل الخطوات اللي جاية وانت مستني؛ السكربت
  بيعرف لوحده لما السجل يشتغل ويطلّع الشهادة ساعتها.

## 5. أول دخول على السيرفر

من جهازك:

```bash
ssh root@<IPv4 بتاع السيرفر>
```

أول مرة هيسألك `Are you sure you want to continue connecting?` اكتب `yes`. لو دخلت من غير
ما يطلب كلمة سر، يبقى المفتاح شغال.

حدّث السيرفر وأعد تشغيله مرة واحدة:

```bash
apt-get update && apt-get -y upgrade && reboot
```

استنى دقيقة وادخل تاني بنفس أمر `ssh`.

## 6. نزول الكود من GitHub

الريبو private، فالسيرفر محتاج مفتاح خاص بيه يقرا بيه الكود بس (Deploy key). على السيرفر:

```bash
ssh-keygen -t ed25519 -C "dental-hub-server" -N "" -f ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
```

انسخ السطر اللي طلع، وعلى GitHub:
الريبو ← **Settings** ← **Deploy keys** ← **Add deploy key**.
- Title: `dental-hub-server`
- Key: الصق السطر
- **Allow write access**: سيبه من غير علامة. السيرفر يقرا بس، ما يكتبش.

وبعدين على السيرفر:

```bash
apt-get install -y git
git clone git@github.com:allinagencyegy-glitch/dental-hub-crm.git /opt/dental-hub-crm
```

هيسألك عن `github.com` أول مرة، اكتب `yes`. نفس المفتاح ده هو اللي `update.sh` بيستخدمه
بعد كده يجيب أي تحديث.

## 7. تشغيل setup.sh

أمر واحد بيجهّز كل حاجة (حط الدومين والإيميل بتوعك):

```bash
bash /opt/dental-hub-crm/deploy/setup.sh --domain crm.example.com --email <إيميلك>
```

الإيميل بيروح لـ Let's Encrypt يبعتلك عليه لو شهادة HTTPS قربت تخلص (ده نادر، لأنها بتتجدد
لوحدها).

بياخد حوالي 5–10 دقايق. بيعمل الآتي بالترتيب:

- يظبط الساعة على توقيت القاهرة، ويضيف swap، ويشغّل التحديثات الأمنية التلقائية و fail2ban.
- ينزّل Node.js 22 و PostgreSQL 17 و Caddy.
- يعمل قاعدة البيانات بكلمة سر عشوائية محفوظة في `/var/lib/dentalhub/shared/.env`.
- يبني البرنامج ويشغّله كخدمة بترجع تشتغل لوحدها لو وقفت أو السيرفر عمل restart.
- يجهّز نسخة احتياطية كل ليلة الساعة 3 الفجر تقريباً.
- يشغّل HTTPS، والشهادة بتطلع وتتجدد لوحدها.
- يقفل الـ firewall على كل حاجة ما عدا SSH و HTTP و HTTPS.

في الآخر هيكتب `==> Done`. لو كتب تحذير إن الدومين لسه ما بيشاورش على السيرفر، ده معناه إن
الـ DNS من الخطوة 4 لسه ما وصلش. مش مشكلة: أول ما يوصل، Caddy بيطلّع الشهادة لوحده من غير ما
تعمل حاجة.

لو السكربت وقف برسالة خطأ، الرسالة بتقول وقف فين. صلّح السبب وشغّله تاني بنفس الأمر؛ تشغيله
أكتر من مرة آمن وما بيمسحش قاعدة البيانات ولا كلمة السر.

## 8. أول حساب أدمن

مرة واحدة بس:

```bash
cd /var/lib/dentalhub/current && sudo -u dentalhub npm run admin:create
```

هيسألك عن الاسم والإيميل وكلمة السر (12 حرف على الأقل، ومش هتظهر وانت بتكتبها). بعدها:

1. افتح `https://crm.example.com` وسجّل دخول بالحساب ده.
2. من **Settings ← Users** ضيف باقي الفريق، واختار لكل واحد دوره (Sales Rep أو Team Leader أو
   Sales Manager أو Admin). المندوب بيتحط على فريق Team Leader من نفس الصفحة.

لو موظف نسي كلمة السر: الأدمن يفتح **Settings ← Users**، ويدوس **Reset password** جنب اسمه،
ويكتب كلمة سر جديدة ويقولهاله. الموظف بيتعمله تسجيل خروج من كل الأجهزة، ويقدر يغيّرها بعد كده
من **Settings ← Password**.

`admin:create` بيرفض لو فيه أدمن شغال بالفعل. لو كل الأدمنز اتقفلوا برّه (نسيوا كلمة السر مثلاً)،
اعمل أدمن جديد بإيميل تاني:

```bash
cd /var/lib/dentalhub/current && sudo -u dentalhub npm run admin:create -- --force
```

بعد كده حمّل قايمة الأسعار في كتالوج المنتجات (مرة واحدة بس):

```bash
cd /var/lib/dentalhub/current && sudo -u dentalhub npm run catalog:import
```

الأمر ده بيضيف موديلات ROSON وToye وFomos وX-Smile وMecco بأسعارها. بعد كده الأسعار بتتعدل من
**Settings ← Products** (المنتجات). لو شغّلته تاني، هيضيف بس الموديلات الناقصة، وعمره ما هيغيّر
سعر اتعدّل من البرنامج.

### نقل العملاء من Spider (مرة واحدة)

بعد قايمة الأسعار، انقل عملاء Spider القدام. هتحتاج ملفات الـ Export (Clients والـ Team) في فولدر
واحد على جهازك، اسمه مثلاً `spider`.

1. ارفع الفولدر على السيرفر (من جهازك):

   ```bash
   scp -r spider root@<IPv4 بتاع السيرفر>:/root/spider
   ```

2. على السيرفر، حطّ الملفات في مكان مقفول على البرنامج بس، وشغّل **تجربة** الأول. التجربة بتقرا
   الملفات وتطبع هيتنقل إيه بالظبط (كام عميل، لمين، بأنهي حالة)، ومن غير ما تكتب أي حاجة:

   ```bash
   install -d -m 700 -o dentalhub /var/lib/dentalhub/spider-import
   install -m 600 -o dentalhub /root/spider/*.xlsx /var/lib/dentalhub/spider-import/
   cd /var/lib/dentalhub/current && sudo -u dentalhub npm run spider:import -- /var/lib/dentalhub/spider-import
   ```

3. لو الأرقام مظبوطة، شغّله بجد:

   ```bash
   cd /var/lib/dentalhub/current && sudo -u dentalhub npm run spider:import -- /var/lib/dentalhub/spider-import --apply
   ```

   بيعمل حسابات الفريق، وكل حساب بكلمة سر عشوائية محدش يعرفها. ادخل **Settings ← Users** واعمل
   **Reset password** لكل واحد، وحطّ كل مندوب على فريق الـ Team Leader بتاعه. لو شغّلته تاني، مش
   هيكرر ولا عميل ولا حساب.

4. امسح الملفات من السيرفر، لأن فيها أرقام العملاء:

   ```bash
   rm -r /root/spider /var/lib/dentalhub/spider-import
   ```

ما تشغّلش `db:seed` ولا `db:seed:acceptance` على السيرفر أبداً. دول لبيانات التجربة على جهاز
المطوّر بس.

## 9. التحديث والرجوع لنسخة قديمة

### تحديث لآخر نسخة

بعد ما أي تعديل يتعمله merge على `main`:

```bash
sudo bash /opt/dental-hub-crm/deploy/update.sh
```

بيجيب آخر كود، ويبنيه في فولدر جديد والنسخة الحالية لسه شغالة، ياخد نسخة احتياطية من قاعدة
البيانات، يطبّق تعديلات قاعدة البيانات، وبعدين ينقل عليه. الموقع بيقف ثواني بس وقت النقل.

- لو البناء أو تعديلات قاعدة البيانات فشلت: ما بيتغيّرش أي حاجة، والنسخة القديمة فاضلة شغالة.
- لو النسخة الجديدة ما ردّتش خلال 30 ثانية: بيرجع للقديمة لوحده.
- لو مفيش جديد بيقولك `Already running ... Nothing to do.`

### الرجوع للنسخة اللي قبلها

لو التحديث اشتغل بس فيه حاجة غلط ظهرت بعدين:

```bash
sudo bash /opt/dental-hub-crm/deploy/update.sh --rollback
```

ده بيرجّع البرنامج بس، مش البيانات. تعديلات قاعدة البيانات اللي التحديث عملها بتفضل، والنسخة
القديمة مصمّمة إنها تشتغل معاها. لو محتاج ترجّع البيانات كمان، فيه نسخة احتياطية اتاخدت قبل
التحديث بالظبط (اسمها فيه `before-update`، شوف الخطوة 10).

### نسخة معيّنة

```bash
sudo bash /opt/dental-hub-crm/deploy/update.sh --ref <tag أو commit>
```

آخر 3 نسخ بس بيتحفظوا على السيرفر. `--help` بيعرض باقي الاختيارات.

## 10. النسخ الاحتياطي والاسترجاع

### النسخة الليلية

كل ليلة حوالي الساعة 3 الفجر بتوقيت القاهرة بتتاخد نسخة من قاعدة البيانات في
`/var/backups/dentalhub/`، ومحدش يقدر يقراها غير root. كل نسخة بتتقري كلها بعد ما تتاخد عشان
نتأكد إنها سليمة، والنسخ الأقدم من 14 يوم بتتمسح لوحدها. `update.sh` و `restore.sh` كمان
بياخدوا نسخة قبل ما يعملوا أي حاجة.

```bash
sudo bash /opt/dental-hub-crm/deploy/backup.sh                 # خد نسخة دلوقتي
sudo bash /opt/dental-hub-crm/deploy/restore.sh                # اعرض النسخ الموجودة
systemctl list-timers dental-hub-crm-backup.timer              # النسخة الجاية امتى
journalctl -u dental-hub-crm-backup -n 20                      # آخر النسخ مشيت إزاي
```

### الاسترجاع

اعرض النسخ، واختار اسم الملف:

```bash
sudo bash /opt/dental-hub-crm/deploy/restore.sh
sudo bash /opt/dental-hub-crm/deploy/restore.sh <اسم الملف>
```

هيطلب منك تكتب `RESTORE` عشان يتأكد. خد بالك: **كل حاجة اتكتبت بعد وقت النسخة دي هتتمسح**،
وده معنى الاسترجاع.

إيه اللي بيحصل: بياخد نسخة من البيانات زي ما هي دلوقتي (اسمها فيه `before-restore`)، ويحمّل
النسخة القديمة في قاعدة بيانات جانبية والموقع لسه شغال، وبعدين يوقّف الموقع أقل من دقيقة ويبدّل
القاعدتين ويشغّله تاني. لو أي خطوة فشلت، القاعدة القديمة بترجع مكانها.

في الآخر بيطبع أمر جاهز للتراجع عن الاسترجاع. لو اكتشفت إنك رجّعت النسخة الغلط، شغّل الأمر ده
وكل حاجة هترجع زي ما كانت قبل الاسترجاع.

### نسخة برّه السيرفر (مهم)

النسخ اللي على السيرفر بتروح لو السيرفر نفسه راح. عشان كده خليك عامل الاتنين:

1. **Hetzner Backups** (من الخطوة 3). لو ما علّمتش عليه وقت الشراء: من Console افتح السيرفر
   ← **Backups** ← **Enable backup**. ده بياخد صورة من السيرفر كله كل يوم ويحتفظ بآخر 7، وتقدر
   ترجّع منه السيرفر كله أو تعمل منه سيرفر جديد.
2. **نسخة على جهازك** مرة في الأسبوع مثلاً. من جهازك (مش من السيرفر):

   ```bash
   mkdir -p dental-hub-backups
   scp 'root@<IPv4 بتاع السيرفر>:/var/backups/dentalhub/*.dump' dental-hub-backups/
   ```

   الملفات دي فيها كل بيانات العملاء، فخليها في مكان آمن ومش متشيّر.

لو احتجت ترجّع ملف من جهازك: ارفعه على السيرفر وادّي `restore.sh` المسار بتاعه:

```bash
scp <الملف>.dump root@<IPv4 بتاع السيرفر>:/root/
ssh root@<IPv4 بتاع السيرفر>
sudo bash /opt/dental-hub-crm/deploy/restore.sh /root/<الملف>.dump
```

## 11. لو حاجة وقفت

ابدأ بالأوامر دي على السيرفر:

```bash
systemctl status dental-hub-crm               # البرنامج شغال؟
journalctl -u dental-hub-crm -n 100           # آخر 100 سطر من سجل البرنامج
curl -s http://127.0.0.1:3000/api/health      # البرنامج شايف قاعدة البيانات؟
journalctl -u caddy -n 50                     # HTTPS والشهادة
systemctl restart dental-hub-crm              # إعادة تشغيل البرنامج
```

| اللي شايفه | غالباً السبب | تعمل إيه |
|---|---|---|
| الموقع مش بيفتح خالص | الـ DNS لسه ما وصلش أو بيشاور على IP غلط | `nslookup crm.example.com` من جهازك، وراجع الخطوة 4 |
| تحذير شهادة أو "connection not secure" | الشهادة لسه ما طلعتش | `journalctl -u caddy -n 50`. اتأكد إن مفيش سجل `AAAA` وإن Cloudflare على DNS only |
| صفحة 502 | البرنامج واقف | `systemctl status dental-hub-crm` و `journalctl -u dental-hub-crm -n 100` |
| تحديث فشل | الرسالة بتقول في أنهي خطوة | النسخة القديمة لسه شغالة. ابعت الرسالة للمطوّر |
| `another update is already running` | فيه تحديث شغال | استنى لما يخلص |
| موظف نسي كلمة السر | | أدمن يعمله واحدة جديدة من **Settings ← Users ← Reset password** (الخطوة 8) |
| كل الأدمنز مش عارفين يدخلوا | نسيان كلمة سر | `admin:create -- --force` بإيميل جديد، وبعدين يعمل Reset password للباقيين (الخطوة 8) |

لما تبعت مشكلة للمطوّر، ابعت معاها آخر سطور من `journalctl -u dental-hub-crm -n 100`، وده
ما فيهوش كلمات سر.

## 12. قواعد الأمان

- ما تبعتش ولا تصوّر ملف `/var/lib/dentalhub/shared/.env`: فيه كلمة سر قاعدة البيانات.
- المفتاح السرّي بتاعك (`~/.ssh/id_ed25519` على جهازك) ما يطلعش من جهازك. لو حد تاني محتاج
  يدخل السيرفر، يعمل مفتاح خاص بيه وتضيفه، بدل ما تديله بتاعك.
- الـ Deploy key على GitHub يفضل read-only.
- ما تفتحش أي port تاني في الـ firewall، وما تشغّلش قاعدة البيانات على الإنترنت. هي شغالة على
  السيرفر من جوّه بس.
- كل موظف ليه حسابه، ويقدر يغيّر كلمة السر بتاعته من **Settings ← Password**. ولما حد يسيب الشغل: **Settings ← Users** ← اقفل حسابه (Deactivate)،
  وبياناته وتاريخه بيفضلوا موجودين.
